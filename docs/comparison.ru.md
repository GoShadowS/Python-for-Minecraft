# Сравнение с Kotlin for Forge и Fabric Language Kotlin

Таблица сравнивает Python-for-Minecraft (PyFM) с двумя референсными проектами по функциям.
Она **не** заявляет паритет. Несколько строк явно помечены «не реализована» с указанием
причины.

**Словарь статусов в колонке PyFM:**

* **реализована и проверена** — код существует, и реально выполненная проверка доказывает, что
  он работает.
* **реализована частично** — код существует, но часть его не проверена или не доделана.
* **не применимо** — функция не имеет смысла для провайдера языка Python, причина указана.
* **не реализована** — отсутствует, причина и план указаны.

Ничего в этой таблице нельзя читать как «весь Minecraft API доступен из Python». Что именно
может достать Python-код, точно описано в [`api.ru.md`](api.ru.md); границу проводит мост
PyFM, а не игра.

## Референсные проекты

| | Kotlin for Forge | Fabric Language Kotlin |
| --- | --- | --- |
| Загрузчик | NeoForge (языковой плагин FancyModLoader) | Fabric |
| Механизм | `modLoader = "kotlinforforge"` в `neoforge.mods.toml`, `loaderVersion = "[5,)"` | `"adapter": "kotlin"` в entrypoints `fabric.mod.json`, `schemaVersion: 1`, класс объявлен в `languageAdapters` |
| Обозначение точки входа | классы/объекты Kotlin | `"pkg.Class"`, `"pkg.FileKt::function"`, `"pkg.FileKt::field"` |
| Версия, виденная здесь | 6.5.0 (ветка `6.x`, min MC 1.21.9, `unsupported_mc_version = 26.4`, toolchain 25, Kotlin 2.2.20) | `1.14.2+kotlin.2.4.21` |
| Распространение | разделение `FMLModType: LIBRARY` + `GAMELIBRARY`, ModDevGradle `JarJar` | один jar с затенённым Kotlin stdlib |
| Проверено по | README и файлы сборки `thedarkcolour/KotlinForForge@6.x`, GitHub API | README `FabricMC/fabric-language-kotlin`, GitHub API |

## Чего PyFM не делает, прямо

* Он не даёт Python-коду «весь Minecraft API». Он даёт Python-коду классы, которые может
  разрешить `pfm.java.import_class`, плюс хендлы, которые отдаёт `pfm.mc`. Доступ к реестрам,
  миксины, отрисовка экранов и манипуляции с датапаками **не** обёрнуты; что-то из этого может
  заработать через прямое Java-взаимодействие, но это не протестировано и не поддерживается.
* Он не переносит стандартную библиотеку Kotlin и рефлексию Kotlin.
* Он не заявляет паритет функций с KFF или FLK: строки 6, 9, 11, 16, 17 и 20 неполны или
  отсутствуют.
* Он ничего не изолирует. Python-мод может сделать всё, что может JVM.
