# Отчёт о тестировании

Всё ниже записано **2026-11-10 12:22 UTC** в среде, где проект был написан: коммит `9336bec`,
ветка `arena/f8d2e234-python-for-minecraft`, Python 3.11.2, Debian 12.

**Словарь статусов:**

| Статус | Значение |
| --- | --- |
| пройдено | Команда была выполнена здесь, и её вывод совпал с ожидаемым. |
| провалено | Команда была выполнена здесь и ожидаемого результата не дала. |
| не запускалось | Команду можно было выполнить здесь, но она не выполнялась. Оправданий такой ячейке нет. |
| заблокировано | Команду нельзя выполнить в этой среде. Причина указана в той же строке. |

Различие существенно: «заблокировано» — это утверждение о песочнице, а не о коде.
Заблокированная ячейка — **не** пройденная, и ни одна заблокированная ячейка нигде в
репозитории не превращена в пройденную.

`net.fabricmc.fabric-loom-remap` с маппингами Mojang и `modImplementation`, Fabric 26.3 —
`net.fabricmc.fabric-loom` без маппингов и обычный `implementation`, а две комбинации NeoForge

## 4. Утверждения, которые намеренно **не** делаются

| Утверждение | Реальность |
| --- | --- |
| «Проверено, что клиентский мод работает без PyFM на сервере» | **Не проверено.** Он так *спроектирован*: `pyhello_client` объявляет `environment: "client"` на Fabric и живёт в клиентском артефакте на NeoForge, а клиентский компонент — отдельный jar со своим id, поэтому на сервере от него ничего не требуется. Запускался ли выделенный сервер без него — никогда не наблюдалось, потому что сервер не запускался вовсе. |
| «Клиент может подключиться к серверу с этими модами» | **Не тестировалось вообще.** Никаких утверждений о соединении клиент↔сервер, протоколе или синхронизации не делается. |
| «Java-код компилируется» | **Неизвестно.** Статическая проверка пройдена (A5/A6). `javac` не запускался. |
| «GraalPy встраивается корректно и Python-моды загружаются» | **Неизвестно.** Сигнатуры Truffle API прочитаны из исходников `oracle/graal`, и код написан против них, но ни один `Context` здесь не создавался. Python-половина протокола протестирована с подставным мостом. |
| «Плагин Shadow работает с Gradle 9.8.2» | **Не проверено.** Записано как риск для матрицы CI. |
| «NeoForge 26.3 использует те же имена классов событий, что в `PyFmNeoForgeServer`/`ClientHooks`» | **Не проверено.** Имена взяты из ветки 21.1; в 26.x они могут отличаться. |
| «Точная патч-версия ModDevGradle — 2.0.90» | **Не проверено.** `projects.neoforged.net` недоступен; `2.0.90` — заглушка с пометкой `TODO(verify)` в `tools/gen_builds.py`. |

## 5. Известные риски, которые должна проверить первая настоящая сборка

1. `com.gradleup.shadow` 9.2.2 против Gradle 9.8.2 — если не заработает, зафиксировать для
   сборок Fabric 26.3 ту версию Gradle, которую плагин поддерживает, и записать изменение.
2. Имена классов событий NeoForge 26.3 в двух классах хуков.
3. `verifyPythonRuntime` уронит сборку ядра, если артефакты GraalPy не содержат
   `META-INF/services/com.oracle.truffle.api.TruffleLanguage$Provider` под этим точным именем.
4. Wrapper-jar'ы Gradle отсутствуют. Их нужно перегенерировать командой
   `gradle wrapper --gradle-version <версия>` в каждом каталоге сборки; CI использует
   `gradle/actions/setup-gradle` и они ему не нужны.

## 6. Как воспроизвести пройденное здесь

```sh
cd python && python3 -m unittest discover -s tests -t .     # 92 теста
python3 tools/validate_metadata.py                          # 30 проверок
python3 tools/validate_metadata.py --self-test              # 4/4 отвергнуто
python3 tools/check_java.py                                 # 34 файла, 33 типа
python3 tools/vendor_deps.py --check \
  --requirements examples/pyhello-common/requirements.txt \
  --out examples/pyhello-common/python/vendor               # six 1.17.0
```

Все пять команд встроены в `./build-all.sh` и в задание CI `python`, поэтому они выполняются
до любой попытки сборки Gradle.
