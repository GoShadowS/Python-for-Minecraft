# Упаковка Python-зависимостей

Python-моды могут использовать сторонние пакеты. Они **вендорятся на этапе сборки и
поставляются внутри jar мода**. Во время игры ничего не скачивается — ни `pip`, ни сети, ни
загрузки при первом запуске. Это жёсткое правило: игра должна запускаться одинаково офлайн, а
скрытная загрузка при старте невоспроизводима.

Инструмент — [`tools/vendor_deps.py`](../tools/vendor_deps.py). Он действительно выполнялся
против PyPI, чтобы создать `examples/pyhello-common/python/vendor/`.

## 1. Объявление зависимостей

`requirements.txt`, с фиксацией версий и хешей точно как файл для
`pip install --require-hashes`:

```
six==1.17.0 \
    --hash=sha256:4721f391ed90541fddacab5acf947aa0d3dc7d27b2e1e8eda2be8970586c3274
```

Нет хешей — инструмент отказывается работать. Не зафиксированные версии — отказывается тоже.
Это намеренно: сборка, разрешающая плавающую версию, не воспроизводима.

## 2. Вендоринг

```sh
python3 tools/vendor_deps.py \
    --requirements examples/pyhello-common/requirements.txt \
    --out examples/pyhello-common/python/vendor
```

Что он делает:

1. скачивает каждый wheel через `pip download --no-deps --only-binary=:all:`;
2. сверяет sha256 с хешем из `requirements.txt` и **падает** при несовпадении;
3. распаковывает wheel в `python/vendor/`;
4. пишет `python/vendor/VENDOR.lock.json` с пакетом, версией, именем файла wheel, хешем и путём
   к файлу лицензии.

Проверить существующее дерево без обращения к сети:

```sh
python3 tools/vendor_deps.py --check \
    --requirements examples/pyhello-common/requirements.txt \
    --out examples/pyhello-common/python/vendor
```

Настоящий вывод из этого репозитория:

```
ok: six 1.17.0 (wheel sha256 4721f391ed90541fddacab5acf947aa0d3dc7d27b2e1e8eda2be8970586c3274)
```

`--clean` сначала очищает выходной каталог, чтобы устаревший пакет не пережил обновление.
`--cache` указывает каталог кэша загрузок (в git не попадает), чтобы повторные запуски не
скачивали заново.

## 3. Поставка

Сборка копирует `python/vendor/` в jar рядом с вашими модулями:

```kotlin
tasks.processResources {
    from("../python") { include("mymod/**"); into("python") }
    from("../python") { include("vendor/**"); into("python") }
}
```

а метаданные называют каталог вендоринга:

* Fabric: `"custom": {"pythonforminecraft": {"vendor": ["python/vendor"]}}`
* NeoForge: `vendor = ["python/vendor"]` внутри `[modproperties.<modId>]`

При старте ядро распаковывает Python-файлы из jar в каталог игры и добавляет их в `sys.path`
мода впереди вендоренных путей, так что мод всегда сначала импортирует свои модули. У каждого
мода свои пути; два мода могут вендорить разные версии одного пакета без конфликта.

## 4. Ограничения — прочитайте до выбора пакета

| Ограничение | Почему |
| --- | --- |
| **Только чисто Python'овые wheel** (`py*-none-any`) | Wheel с компилируемым расширением содержит бинарник под конкретную платформу. PyFM не поставляет и не загружает такие: нет native-image-сборки, нет артефактов под каждую ОС и нет способа проверить такой бинарник здесь. |
| Нет разрешения транзитивных зависимостей | `--no-deps` используется намеренно. Транзитивные зависимости нужно перечислять явно и фиксировать по хешу. Так lock-файл остаётся честным. |
| Нет `pip` в рантайме | По замыслу. Если пакету нужна кодогенерация на этапе установки, он не заработает. |
| Нет пакетов на C-расширениях | Всё, что в итоге требует `numpy`, `pillow`, `cryptography`, `lxml` и подобное, не загрузится. GraalPy поддерживает многое из этого через собственные управляемые установки, но для этого нужен образ рантайма GraalPy и артефакты под каждую платформу, чего этот проект не поставляет. |
| Лицензии не проверяются | Инструмент записывает *путь* к файлу лицензии, но судить о лицензии не может. Ответственность на вас; см. [`../THIRD_PARTY_LICENSES.md`](../THIRD_PARTY_LICENSES.md). |

## 5. Чек-лист воспроизводимости

* [ ] `requirements.txt` фиксирует точные версии с хешами
* [ ] `python/vendor/` закоммичен, а не в git-ignore
* [ ] `python/vendor/VENDOR.lock.json` закоммичен
* [ ] `tools/vendor_deps.py --check` проходит в CI
* [ ] лицензия каждого завендоренного пакета совместима с лицензией вашего мода

CI выполняет шаг `--check` для примера `pyhello_common` на каждый push.
